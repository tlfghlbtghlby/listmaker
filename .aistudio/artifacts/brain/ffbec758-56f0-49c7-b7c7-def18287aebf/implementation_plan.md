# خطة تنفيذ حفظ القوائم قيد الإعداد وتعليقها وتعدد الفواتير السريع (Multi-Draft POS Orders)

تهدف هذه الخطة إلى تلبية متطلبات المستخدم بدقة: الحفاظ التام على القوائم قيد الإعداد عند التصفح بين أقسام التطبيق بدون فقدانها، مع توفير زر سلة مهملات بحوار تأكيد لحذف القائمة، وزر (+) لتعليق القائمة وبدء قائمة جديدة، ومربعات خضراء مرقمة [1]، [2]، [3] للتبديل الفوري بين القوائم المعلقة.

---

## 1. قرارات المستخدم ومواصفات الواجهة المتفق عليها (User Decisions & Clarifications)

1. **بقاء القائمة وعدم اختفائها عند التصفح**:
   - تخزين القوائم النشطة قيد الإعداد وحالتها في الذاكرة المشتركة والتخزين المحلي (`localStorage`) بحيث لا تُفقد عند الانتقال بين نقطة البيع (POS) والمخزن أو الفواتير أو الزبائن أو الشفتات أو الإعدادات أو حتى عند إعادة تحميل الصفحة.
2. **زر سلة المهملات بجانب نوع البيع (مباشر / آجل)**:
   - وضع أيقونة سلة مهملات حمراء/رمادية أنيقة بجانب شريط اختيار نوع البيع.
   - **نافذة تأكيد مشددة**: عند النقر عليها، تظهر نافذة تأكيد واضحة ومباشرة لتجنب الحذف بالخطأ، وعند التأكيد يتم تفريغ القائمة وإعادة تعيينها.
3. **زر (+) لتعليق القائمة الحالية وبدء قائمة جديدة**:
   - زر (+) أخضر بجانب سلة المهملات يُتيح تعليق الفاتورة الحالية وفتح قائمة جديدة فارغة في ثوانٍ.
4. **مربعات خضراء أنيقة مرقمة [1]، [2]، [3] للتبديل بين القوائم**:
   - عرض أزرار مربعة خضراء أنيقة تحتوي **فقط على رقم القائمة** بدون أي تفاصيل مشتتة (كما اختار المستخدم تحديداً في الأسئلة).
   - تمييز المربع النشط باللون الأخضر الزمردي الداكن مع رقم ناصع، وتغيير الترتيب والتبديل بسلاسة بين القوائم بنقرة زر واحدة.
5. **معالجة حفظ وطباعة القائمة**:
   - عند إتمام بيع أو طباعة القائمة الحالية، تُحذف هذه القائمة المكتملة من قائمة المسودات ويتم الانتقال تلقائياً للقائمة المعلقة التالية إن وُجدت، أو فتح قائمة أولى جديدة فارغة.

## 2. الهيكل المعماري والبيانات (Architecture & Data Model)

### نموذج بيانات مسودة القائمة (`POSDraftOrder`):
```typescript
export interface POSDraftOrder {
  id: string;             // معرف المسودة الفريد
  orderNumber: number;    // رقم القائمة التسلسلي المعروض في المربع (1، 2، 3...)
  cartItems: InvoiceItem[];
  saleType: 'direct' | 'credit';
  globalPriceType: 'retail' | 'wholesale';
  selectedCustomerId: string;
  customCustomerName: string;
  customerPhone: string;
  discount: number;
  paidAmount: number;
  dueDate: string;
  notes: string;
  updatedAt: string;
}
```

### إدارة الحالة المشتركة (Shared State Management):
- إضافة الحالة والتوابع إلى `AppContext.tsx` أو hook مخصص مدعوم بالـ Context:
  - `draftOrders: POSDraftOrder[]`: مصفوفة القوائم (تحتوي دائماً على قائمة واحدة على الأقل).
  - `activeDraftId: string`: معرّف القائمة المعروضة حالياً.
  - `switchToDraft(id: string)`: التبديل لقائمة معلقة.
  - `addNewDraft()`: تعليق الحالية وبدء قائمة جديدة (+).
  - `clearCurrentDraft()`: تفريغ/حذف القائمة الحالية بعد التأكيد.
  - `removeDraft(id: string)`: حذف المسودة بعد إتمام البيع بنجاح.
  - حفظ تلقائي فوري في `localStorage` بمفتاح `cached_pos_draft_orders`.

### 3. تحديث واجهة نقطة البيع `src/components/POSView.tsx`:
- ربط بيانات السلة والعميل والخصومات بالقائمة النشطة `activeDraft`.
- تحديث ترويسة بطاقة الفاتورة:
  - بجانب أزرار "بيع مباشر (نقدي)" و "بيع آجل (دين)":
    - **مربعات خضراء مرقمة**: `[1]`, `[2]`, `[3]` ... تُظهر رقم القائمة المعلقة فقط. المربع النشط يكون بلون أخضر ممتلئ، بينما القوائم الأخرى بألوان متناسقة.

    - **زر سلة المهملات (Trash)**: أحمر/رمادي لحذف القائمة الحالية مع استدعاء نافذة التأكيد.
- إضافة نافذة تأكيد حذف القائمة `ConfirmClearCartModal`:
  - رسالة واضحة: "هل أنت متأكد من رغبتك في حذف وتفريغ القائمة الحالية (رقم X)؟"
  - زران: "نعم، حذف القائمة" و "إلغاء".
- عند الضغط على حفظ وطباعة الفاتورة، يُستدعى `completeActiveDraft` ليتم مسح المسودة المكتملة والانتقال تلقائياً للقائمة التالية.
